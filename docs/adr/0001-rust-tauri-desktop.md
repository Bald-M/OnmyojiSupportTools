# ADR-0001：采用 Rust + Tauri 桌面架构

- 状态：已接受
- 日期：2026-09-09

## 背景

原项目使用 Koa 本地 HTTP 后端和独立 Vue 页面。首个可交付目标只需要在 Windows 上安全地管理 ADB、设备、截图和坐标点击；继续维护网络层与多包工作区会扩大攻击面、部署面和状态同步成本。长期设想中的识别、任务和调度尚未形成稳定领域模型。

## 决策

采用 Rust、Tauri 2 和 Vue 3 的单体桌面结构。Vue 负责本地 WebView 界面，Rust `DeviceManager` 负责全部设备状态与外部进程，通过有限的 Tauri IPC 命令连接两者。移除 Koa、本地 HTTP、浏览器部署和 Lerna 工作区。

首版不实现任务运行时、识别、OCR、调度、插件、多设备并发或远程控制。先稳定单活动设备的人工检查链路，再用新的 ADR 评估扩展边界。

## 取舍

优点是产物单一、进程与状态边界清晰，Rust 适合约束外部命令、二进制截图和并发操作；Tauri 可以复用 Vue 生态并使用 Windows WebView2。代价是 Windows 构建需要 Rust/MSVC/WebView2 工具链，且未来 macOS 支持仍需平台发现、签名和验收工作。

选择 Electron 会获得更一致的渲染运行时，但安装体积和资源占用更高；继续使用 Koa 会保留浏览器可访问的网络边界；立即构建任务运行时则会在核心设备契约稳定前固化错误抽象。因此三者均未采用。

## 约束

- 不监听 HTTP 端口，不提供浏览器部署。
- ADB 调用不经过 shell，并具有超时与终止策略。
- 截图保持二进制传输和设备归属校验。
- Windows 是当前唯一受支持平台，macOS 只保留可扩展结构。
