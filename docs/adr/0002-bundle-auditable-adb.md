# ADR-0002：Windows 安装包携带可审计的 ADB

- 状态：已接受
- 日期：2026-09-10

Windows 用户发布物采用可卸载的 NSIS 安装包，并携带固定版本、校验值和许可证材料齐全的 AOSP ADB 构建产物，从而在未安装 Android SDK 的环境中也能直接使用。`src-tauri/adb-distribution.json` 是版本、来源和哈希的唯一机器可读清单。构建流程从 Google 官方 Platform-Tools 地址取得版本 `37.0.1`，在打包前校验 ZIP 及所选文件的 SHA-256；应用启动时再根据编译进主程序的同一清单复核安装文件和版本。应用运行时不下载或反编译 ADB，用户仍可显式选择模拟器或 SDK 提供的外部 ADB。

内置 ADB 保持独立进程，由 `DeviceManager` 通过结构化参数和超时调用，并使用应用专用的本机 server 端口 `5038`。端口空闲时显式执行 `start-server`；身份探测不运行 ADB 客户端，而由 Rust 直接发送只读的 smart-socket `host:server-status` 请求并核对服务端版本与可执行文件路径，避免 ADB 客户端在版本不匹配时自动重启未知实例。端口已占用时只接受版本与路径都指向当前内置 ADB 的实例，用于回收应用异常退出留下的 server。退出前再次核对身份，匹配后才执行 `kill-server`。版本或路径不匹配、或无法验证时拒绝接管并提示用户改选外部 ADB，因此不会主动终止通常位于 `5037` 或预先占用 `5038` 的外部实例。代价是构建依赖固定的上游归档、安装体积增加，并且每次升级都必须重新核对来源、哈希、NOTICE 和 Windows x64 验收结果。
