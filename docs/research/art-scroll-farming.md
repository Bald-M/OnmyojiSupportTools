# 绘卷、困 28、结界突破与远程 Windows：研究记录

核查日期：2026-10-11（中国标准时间）。这里只把游戏运营方、UU 开发者及本项目自身材料当作一手证据；游戏中的现行界面仍须在用户的 Windows 实机上核对。本文不含游戏截图、素材、模板或第三方自动化代码。

## 可确认的事实

1. **追忆绘卷是限时活动，规则随活动期而定。** 网易《阴阳师》官方账号在 2024-08-11 公布的遥念烟烟罗绘卷活动规定：2024-08-14 维护后至 2024-09-03 23:59 开放；六张绘卷分别捐赠、分别排名；参与游戏内玩法获取碎片，捐赠碎片修复绘卷、获得随机奖励。这说明“刷绘卷”至少涉及碎片获取与捐赠两个不同环节，且需要在每期活动开始时读取该期规则，不能把历史活动时间写死。[官方微博，2024-08-11](https://weibo.com/5896401674/OrKAlpWe0)。
2. **即使活动标称期限未到，也可能失去继续获取碎片的机会。** 网易游戏小管家发布的 2026-06-24 维护公告明确称，毗沙门天绘卷的活动期为 2026-06-24 维护后至 2026-07-14 23:59；全服绘卷全部修复后，不能继续获得碎片或修复绘卷。该公告只证明那一期的规则，并不证明 2026-10-11 正在运行哪一期活动。[网易游戏小管家公告，2026-06-24](https://community-cn.honor.com/cngm/game/topicdetail/topicid-3737749198733313)。
3. **当前仓库的受支持设备路径是运行应用的 Windows 主机上的 ADB。** README 规定 Windows x64、MuMu 12/雷电 9 为支持目标；`DeviceManager` 统一管理 ADB、设备、截图、点击与任务会话；当前不提供远程控制或 macOS 原生运行。现有结界突破循环与校准可复用，但它只处理结界突破，不含困 28 探索及二者切换。[README，核查于 2026-10-11](../../README.md)、[CONTEXT.md，核查于 2026-10-11](../../CONTEXT.md)。
4. **UU 远程提供远端桌面画面和人工操控，但这不等于本应用自动获得远端模拟器的 ADB 设备。** 网易发布的 UU 远程 App 描述将其定位为跨设备远控电脑与游戏串流，并另列文件传输、远程终端、端口映射等功能。由此结合本项目的本机 ADB 架构可推断：用户通过 UU 看到 Windows 游戏画面，只解决人工访问 Windows 的问题；应用若仍运行在开发用 macOS 上，不会仅因为 UU 会话建立就枚举到 Windows 上的 MuMu ADB。最直接的既有部署路径是把 Windows x64 安装包与模拟器运行在同一台被控 Windows 主机上，再通过 UU 查看和人工控制应用。是否能在该远端主机启动安装包、启用模拟器 ADB，需要实机验证。[网易 UU 远程 App 描述，页面核查于 2026-10-11，页面所列最新版本 4.42.0 于 2026-09-25 发布](https://apps.apple.com/cn/app/uu%E8%BF%9C%E7%A8%8B-%E8%BF%9C%E7%A8%8B%E5%8A%9E%E5%85%AC-%E6%B8%B8%E6%88%8F%E4%B8%B2%E6%B5%81/id1642306791)、[README](../../README.md)。
5. **自动刷图存在明确的账号处罚风险。** 网易官方《网易用户协议》第十九条把未经许可、能在游戏中取得优势的第三方程序纳入处理范围，举例包含自动练级、自动完成任务；列出的措施包括没收不当利益、冻结玩法、强制离线及禁止登录。自动刷困 28、自动突破与该条举例高度相关。该通用协议是否被当前《阴阳师》账号使用、是否存在专门许可或例外，尚未通过游戏内协议页核实；开发和使用前应先核对账号实际接受的协议及官方许可状态。不能把“通过 ADB 点击”或“通过 UU 远程”当作合规豁免。[网易用户协议，第十九条；页面未标发布日期，2026-10-11 访问并核对原文](https://protocol.unisdk.netease.com/release/latest_v1.html)。

## 对后续 Issue 的直接影响

- 用户已决定第一版只自动执行困 28 与结界突破循环，绘卷碎片由用户手动捐献；战斗完成次数不能充当碎片获得量。
- 先把 **Windows 主机上安装、连接和识别同机模拟器** 列为验收前提，不能把 UU 远程会话当作 ADB 传输层。现有项目不支持把应用当成 macOS 控制端直接操作 UU 画面。
- 把 **官方许可与账号风险确认** 设为明确的决策项。研究中没有找到对这类第三方自动化的许可；通用协议的禁令应如实写入风险，不能提出规避处罚或检测的方案。
- 以 **实机观测驱动** 困 28、挑战券阈值与切换状态的规格。每次点击前先识别当前页面；无法确认资源、目标或动作时暂停，而不是依据历史攻略继续操作。
- “刷绘卷”不应只以战斗次数计数；应分别观察战斗结算、实际碎片获得、活动是否仍开放、体力/券数。由于活动可提前完成，本期有效性是任务启动及运行中的条件。
