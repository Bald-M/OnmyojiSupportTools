# Windows 手工验收矩阵

在发布候选产物上执行本矩阵。记录应用构建编号、模拟器精确版本、ADB 版本、执行人和日期；提交记录前对路径、IP 与设备序列号脱敏。

## 环境组合

| Windows | MuMu 模拟器 12 | 雷电模拟器 9 |
| --- | --- | --- |
| Windows 10 22H2 x64 | 待验证 | 待验证 |
| Windows 11 x64 | 待验证 | 待验证 |

每个组合都应检查 Windows x64 NSIS 安装包，并在没有 Android SDK、`PATH` 中没有 ADB 的干净环境中至少执行一次完整流程。

## 基础流程

- [ ] 首次安装后自动验证并选择内置 ADB，显示“应用内置”和版本 37.0.1。
- [ ] 自动发现模拟器自带 ADB，并允许从内置 ADB 切换到外部 ADB。
- [ ] 手动选择有效 `adb.exe` 后通过验证；选择无效文件时给出可恢复错误。
- [ ] 单台在线设备自动成为活动设备。
- [ ] 多台设备时要求用户选择；活动设备列表只显示在线可操作设备，离线和未授权设备通过诊断信息处理而不占据选择列表。
- [ ] 有效 IP/端口可以连接；无效 IP、端口和不可达端点提供明确反馈。
- [ ] 启动一个未手动连接的 MuMu 12 实例后，应用初始化或刷新可自动发现、连接并选择该设备。
- [ ] 同时运行多个 MuMu 12 实例时，所有实例均出现；端口占用导致端口偏移时仍可通过监听端口所属进程发现。
- [ ] MuMu 多开器只运行两个已命名实例时，活动设备列表恰好显示这两个窗口实例名称；同 Android 型号仍可区分，关闭实例及 ADB 遗留离线 endpoint 不显示。
- [ ] 一个 MuMu 实例连接或属性验证失败时，其余 ADB 设备仍可使用并显示诊断信息；关闭活动实例后旧截图、坐标、预览和任务上下文失效。
- [ ] 没有 MuMu 运行时不连接无关本地端口，手动 IP/端口连接仍可作为回退。
- [ ] “刷新截图”每次获取一帧，操作期间界面可响应且不能重复提交。
- [ ] 横向和纵向留白、窗口缩放后，画面中心与四角坐标映射正确。
- [ ] 单击画面只移动十字标记，不立即操作设备。
- [ ] X/Y 可由键盘编辑；越界值禁用“执行点击”。
- [ ] “执行点击”只在当前活动设备、当前截图和有效坐标下成功。
- [ ] 切换设备后截图与坐标立即清除。

## 异常与恢复

- [ ] 模拟器关闭、设备离线和设备未授权时不保留无效活动状态。
- [ ] ADB 超时后子进程被终止，状态栏给出重试方式，界面恢复可操作。
- [ ] ADB 返回非 PNG 数据时拒绝显示和点击。
- [ ] 连续替换截图时内存不会持续增长。
- [ ] 内置 ADB 缺失、损坏、版本或校验不符时构建失败或应用提示重新安装/选择外部 ADB，应用运行时不会下载替代文件。
- [ ] 内置 ADB 使用端口 5038；异常退出后可按 smart-socket `server-status` 返回的版本和程序路径回收自有实例，其他程序预先占用时拒绝接管，正常退出前再次核对身份，端口 5037 上的外部 ADB server 不受影响。

## 安装、升级与卸载

- [ ] x64 用户发布物只有带版本、平台和架构名称的 NSIS `.exe` 安装包。
- [ ] 构建完成后 `dist/` 中只有该 NSIS 安装包，不存在旧安装包或便携 ZIP。
- [ ] 安装目录包含 `adb.exe`、两个 ADB DLL、`NOTICE.txt`、`source.properties` 和 `PROVENANCE.json`。
- [ ] Windows“已安装的应用”中存在卸载入口，正常卸载后应用安装目录及内置 ADB 文件被移除。
- [ ] 升级或卸载不会删除 Android SDK、模拟器文件、用户手动选择的 ADB 或其他应用的数据。
- [ ] 安装、升级和卸载不会启动 HTTP 监听，也不会在应用运行时下载 ADB。

## 性能与资源

- [ ] ADB 列举、连接、截图和点击期间窗口可移动，状态反馈持续可见。
- [ ] 单次“刷新截图”只产生一次 `screencap` ADB 进程，不出现额外编码步骤。
- [ ] 连续替换截图 50 次后，应用内存回落到稳定区间，不随次数持续增长。

## 实时预览原型（Issue #4）

- [ ] Windows x64 + MuMu 12 的 1280 × 720 画面连续显示；记录平均、P95 和最低 FPS，目标为稳定 30 FPS。
- [ ] 使用画面内毫秒计时器或高速摄像测量模拟器变化到应用显示的延迟；记录至少 30 次样本，目标 P95 不高于 150 ms。
- [ ] 连续运行 30 分钟，每分钟记录应用、ADB 和 WebView2 子进程的工作集、私有字节与句柄数；确认没有持续增长趋势。
- [ ] 连续执行开始 → 停止 → 再开始 10 次，停止后没有遗留 `screenrecord`、ADB 子进程或端口转发。
- [ ] 预览中点击画面只选择坐标，按下“执行点击”后才操作当前设备。
- [ ] 切换设备、设备离线、关闭模拟器和退出应用都会终止旧会话并清除坐标。
- [ ] WebCodecs 不可用或解码失败时有可恢复提示，停止后静态截图仍可使用。

详细记录模板见 [Issue #4 实时预览原型](prototypes/issue-4-live-preview.md)。

## 活动自动挑战（Issue #13）

- [ ] 四向拖拽、窗口缩放及横纵留白下，矩形区域均映射到相同设备像素；小于阈值的拖拽按单点处理。
- [ ] 单点和矩形的随机延时、最终落点与按压时长均在配置范围内；等待期间取消后没有 ADB 输入。
- [ ] 完成活动入口、关卡入口、首次挑战页、战斗中、奖励页和返回挑战页六态校准；配置文件不含 PNG、裁剪图或可还原像素。
- [ ] 唯一识别六类画面，低置信度、双状态歧义、尺寸或方向变化均暂停且不点击。
- [ ] 首次导航、1 次和连续 N 次循环只在领取奖励并返回挑战页后计数。
- [ ] 战斗中没有 ADB 输入；达到目标、暂停、停止及应用退出后没有后续输入。
- [ ] 截图或 ADB 瞬时失败按有限退避恢复，第三次耗尽或状态超时后安全暂停。
- [ ] 本机已知悬赏仅点击配置关闭区域；未知弹窗和重复超过上限均暂停。
- [ ] 暂停后先显示新截图识别结果，只有用户确认后恢复；重启应用保持空闲。
- [ ] MuMu 12 连续运行 30 分钟，截图和特征处理内存无持续增长。

## 鼠标区域编辑（Issue #24）

以下项目必须在 Windows x64 的原生 Tauri/WebView2 窗口验收。自动化及交叉构建证据见 [Issue #24 验证记录](qa/issue-24/README.md)，不能替代这些项目。

- [x] 原生执行 `pnpm check`、`pnpm frontend:build`、`pnpm build:windows:x64`；确认版本、Windows、x64 均出现在安装包名称中。已由 [Windows CI run 34732873992](https://github.com/Bald-M/OnmyojiSupportTools/actions/runs/34732873992) 完成。
- [ ] “创建区域”支持四向框选，实时尺寸与原始像素一致；横纵留白不能开始框选，边界和单像素区域合法。
- [ ] 调整窗口大小后，从默认 40 × 40 及更小区域开始，拖动内部或中心十字移动，八个手柄均可放大/缩小且不互相遮挡；小选区外围手柄不改变原始像素边界。
- [ ] 移动保持尺寸；画面外释放后编辑结束，再移动鼠标没有后续变化；取消或失去指针捕获后可重新编辑。
- [ ] 松开后的 click 保留矩形；数字精调立即更新覆盖层，负数、越界和零宽高都限制为合法边界；“选择单点”返回取点模式。
- [ ] 区域可提交随机点击、识别区域、动作区域、弹窗识别和关闭区域；仅“执行点击”触发手动设备输入，编辑本身没有输入。
- [ ] 拖拽中刷新截图、停止预览、切换设备、设备离线或切换 ADB 后旧目标和编辑状态均清除；明暗画面下边界、手柄和尺寸清晰。
